## Status

Active. The unified/remark/rehype packaging gate is proven, the initial product rulings are recorded, and [[wa.task.2026.2026-09-11_1153-markdown-contract-safety-fixtures]] is the first fireable child.

## Goals

- Render mesh-held Markdown DigitalArtifacts—developer docs, user guides, and explicitly opted-in conversation transcripts—as ResourcePage content rather than raw-source panels.
- Support the narrow first Dendron profile: filename-hierarchy identity, durable frontmatter aliases, target/alias/heading wikilinks, and mesh-state-aware resolution.
- Converge Markdown, HTML fragments, and plain text on one safe compiled-content representation without putting filesystem, RDF, or network access into templates.
- Preserve deterministic Deno/Node output and make renderer changes explicit, reviewable epochs.
- Expose complete site building through the public API only after the internal pipeline is proven and its API contract is separately ratified.

## Summary

This work is a static-site-generator arc, not a renderer swap. The hand-written Markdown renderer in `src/runtime/weave/pages.ts` is incomplete and accepts active URI schemes such as `javascript:`. The intended endpoint also needs cross-document indexing, Dendron wikilink resolution, derived facts, multiple input syntaxes, sanitization, and a packaged Node API. Those concerns require ordered, independently reviewable tasks and several evidence gates.

The architecture evaluation and detailed evidence live in [[wa.discussion.2026-08-08-markdown-renderer]]. `unified`/`remark`/`rehype` won because its mdast/hast boundary supports the required indexing and transformations. The earlier `markdown-it` choice was sound for the narrower render-only question and is superseded for this larger scope.

The ResourcePage presentation foundation is already delivered by [[wa.completed.2026.2026-05-22_2253-resourcepage-config-and-templating]]: document and panel models, presentation-policy resolution, built-in template and stylesheet identities, custom-page composition, and a data-only external-template contract. This plan builds the authored-content compiler and site-generation path on that foundation; it does not restart templating.

## Sequence

1. Land the contract, link-safety, and baseline-fixture child.
2. Introduce a data-only source/compiled-content boundary populated by the existing renderer so generated bytes do not move.
3. Add the unified Markdown compiler behind unit tests without routing production pages through it.
4. Add two-pass Dendron discovery, duplicate detection, wikilink nodes, resolution, and diagnostics.
5. Cut authored pages over behind an explicit renderer version; keep the direct fallback on the same compiled result.
6. Add sanitized HTML-fragment and plain-text adapters through the common compiled-content tail.
7. Make eligible Markdown DigitalArtifacts render as their own page content rather than raw-source panels.
8. Run the renderer-epoch publication diff, switch the official renderer, and delete the regex renderer and direct-rendering bypass.
9. Ratify and implement the public site-building API as its own contract child.

Steps 2–9 remain serial unless a child task proves that a file-disjoint supporting bite can safely run in parallel. Do not cut speculative children merely to populate the plan.

## Gates

- **G0 — presentation substrate: PROVEN.** Shared ResourcePage document/panel assembly, presentation policy, custom-page opt-in, built-in presentation assets, and the template request/result boundary are delivered.
- **G1 — packaging: PROVEN.** Evidence branch `lane/spike-unified-packaging` at `e84fdba` rendered real Dendron Markdown under Deno and Node with byte-identical output. The 1,467-document probe peaked at 242 MB in Deno and 233 MB in Node. The branch is evidence only and must not merge because it carries a temporary npm export.
- **G2 — first child acceptance.** Unsafe active URI schemes are fail-closed, allowed existing links still resolve, representative authored output has a byte/hash baseline, the ruled Dendron v1 cases are captured, and full CI is green.
- **G3 — compiler parity.** Exact dependency pins and a frozen lock produce deterministic Deno and packed Node rendering, with hostile inputs sanitized and no production routing change.
- **G4 — cutover review.** A fixed-timestamp scratch regeneration has a reviewed publication diff; every intentional byte change is attributed to the renderer epoch before official fixtures or publications move.
- **G5 — public API ratification.** A durable API contract note defines request/result/error/atomicity and Deno/Node parity before any site-building export is added to `src/api/mod.ts`.

## Decisions

- Use `unified`/`remark`/`rehype`, not `markdown-it`, for the site-generator endpoint.
- Use a two-pass pipeline: discover/index first, compile and resolve second.
- Keep mdast/hast inside runtime. Core receives a serializable compiled-content model rather than parser trees or executable plugins.
- The Markdown front end does not enable raw embedded HTML in the first cut. Every syntax adapter enters one sanitizer-controlled hast tail.
- A note's filename hierarchy determines its designator path and readable IRI. Its Dendron frontmatter `id` is recorded as a durable alias. Each vault mounts under a distinct designator prefix.
- Wikilink v1 supports target, alias, and heading-anchor forms only. Note references, block references, and tags are out of scope.
- A missing or unpublished wikilink target renders as a disabled link rather than failing the build or silently becoming plain text.
- Conversation transcripts are unpublished by default and require explicit opt-in.
- Compose from content and reference from identity: shared fragments may be `ResourcePageSource`s, while peer resources should normally be linked rather than borrowed as page bodies.
- Knop rename/supersession behavior is owned by [[wa.task.2026.2026-08-06_0949-knop-supersession-and-rename]] and does not block this plan's first eight steps.
- Site building through the public API is the endpoint, but it is the last separately ratified child rather than an incidental export.

## Open Issues

These are later gate questions and do not block the first child:

- Exact frontmatter required/optional fields and precedence when frontmatter disagrees with RDF metadata.
- The standalone HTML-fragment sanitizer schema beyond the unconditional ban on scripts, event handlers, and active URL schemes.
- Whether plain text renders as literal `<pre>` or paragraphized text.
- Which DigitalArtifact roles/media types become navigable pages automatically.
- Whether derived headings, links, and text remain transient render data or become materialized RDF with provenance.
- Whether byte stability is promised only for official frozen-lock builds or also for fresh third-party npm installs.
- Whether the renderer epoch preserves the current shell or deliberately regenerates it.
- Whether CI should assert the exact production dnt entry-point set before the public API child; the packaging spike proved branch discipline alone can let a temporary export approach release machinery.

## Testing And Receipts

- Packaging receipt: repeated in-process renders, fresh-process renders, and Deno-versus-Node renders were byte-identical on the evidence branch.
- Scale receipt: 100/500/1,467 real-document renders showed bounded memory rather than accumulation; the largest Deno observation was 5.83 seconds / 242 MB.
- Each implementation child must add focused unit coverage and run validation proportional to its boundary. Production cutover, DigitalArtifact routing, and the API surface require full `deno task ci` plus packed Node smoke coverage.
- Renderer-epoch acceptance compares fixed-timestamp output by bytes/hashes and reviews the whole publication diff rather than relying on DOM equivalence.

## Non-Goals

- Retiring `ResourcePageSource` for genuine shared content fragments.
- Implementing arbitrary executable third-party templates or giving templates RDF/filesystem/network access.
- Making raw HTML in Markdown trusted.
- Adding note refs, block refs, tags, search ranking, rich-result promises, or HTML-to-Turtle round-tripping in the first pipeline release.
- Solving Knop rename/supersession inside the Markdown renderer.
- Merging the packaging spike or its temporary npm export.

## Exit Criteria

- Eligible mesh-held Markdown DigitalArtifacts render safely as their own ResourcePage content with the ruled Dendron behavior.
- Markdown, supported HTML fragments, and plain text share one compiled-content and sanitization tail.
- Official Deno and packed Node builds render deterministically under exact dependency pins and pass the scale guard.
- The official renderer epoch has a reviewed publication diff and the old regex/direct bypasses are removed.
- Public site building is contract-ratified, exported, documented, and verified through source and installed-library paths.
- Superseded renderer tasks and affected backlog/roadmap guidance are reconciled, and no required follow-up remains only in this plan's prose.
