## Goals

- Replace whole-corpus page rendering with bounded render → write → discard execution.
- Preserve generated bytes and the existing result/report surface: generated designator paths plus created, updated, and timestamp-only-skipped paths.
- Meet the scale epic's working generate target at N=1,700 on the faithful current-only nested-source workload: peak RSS under 1.5 GiB and N=500 → N=1,700 growth no worse than linear.

## Summary

Carved from [[wa.completed.2026.2026-08-02_1330-extracted-term-weave-batch-path]] under Dave's 2026-08-06 ruling that generate belongs to the scale epic as its own lane. PR #41 already fixed the weave-side quadratic path, and PRs #43/#44 repaired the MeshInventory history-index output. That landed weave work cannot establish extract→weave→generate viability by itself: the original N=1,700 probe measured standalone generate at 3.74 GiB peak RSS, nearly the same ceiling exposure as weave.

The diagnosed generate accumulation has no cross-page link index and therefore no ordering constraint requiring whole-corpus rendered-byte residency. Current execution loads every `ResourcePageModel`, starts every render through one unbounded `Promise.all`, returns all rendered bytes as `readonly PlannedFile[]`, and only then writes. This carve changes that shape to bounded render batches whose completed pages are written in canonical input order and discarded before the next batch.

Completed 2026-08-21 at Weave `5fd9dd1`. Full generation now visits models in canonical order, shares decoded raw-source contents by absolute path for the command, and renders/writes/discards batches of at most four pages. `GeneratePreparedPagesResult`, CLI summaries, timestamp-only skip behavior, and generated bytes remain unchanged. Generate-side `WEAVE_MEMORY_STATS` reports rendered pages, batches, maximum batch files/bytes, and peak RSS.

## Discussion

Consumer audit against Weave `main` at `f505247`:

- standalone `executeGenerate` consumes only `GeneratePreparedPagesResult` path arrays;
- composed `executeWeave` merges those same path arrays into `WeaveResult`;
- version-time MeshInventory history-index regeneration consumes the same internal page-generation pipeline and returns only created/updated/skipped paths;
- CLI reporting counts those arrays;
- no dry-run, diff, publication, or public API consumer reads the rendered `PlannedFile[]` payload;
- `collectGeneratedPageFiles` is exported only from the internal runtime module and has no repository caller outside that module.

Therefore the `PlannedFile[]` materialization is an internal implementation artifact, not a result contract. The result shape can remain byte-free while rendered page contents become batch-local.

The model assembler also accumulates every `ResourcePageModel`. Its corpus-wide contexts and child/history lookup structures remain necessary to preserve current page semantics, but the final model array does not: expose model iteration, retain the shared context, and feed bounded render/write batches without retaining completed models or bytes.

Final faithful curve:

| N | standalone generate wall / max RSS | rendered pages / batches / max batch files |
|---:|---|---|
| 500 | 10.61s / 357 MiB | 2,014 / 504 / 4 |
| 1,000 | 32.86s / 524 MiB | 4,014 / 1,004 / 4 |
| 1,700 | 1m34.12s / **674 MiB** | 6,814 / 1,704 / 4 |

N=500→1,700 RSS growth is 1.89× for 3.4× cardinality, below the ruled linear bound and well below the 1.5 GiB endpoint target. The old N=1,700 result was 2m29.63s / 3.74 GiB.

## Decisions

- **RULED 2026-08-06 (Dave):** generate is in scope for the extracted-term scale epic as its own carve. No extract→weave→generate viability claim may rest on the weave carve alone.
- **RULED 2026-08-06 (Dave):** apply the same working target as weave: N=1,700 peak RSS under 1.5 GiB and growth from N=500 to N=1,700 no worse than linear; growth shape is the load-bearing condition.
- Preserve canonical model/write ordering while bounding only the number of simultaneously rendered pages. Concurrency remains an internal constant, not a new user-facing configuration contract.

## Contract Changes

None intended. Generated bytes, generated page selection, timestamp-only skip behavior, diagnostics, returned paths, and their ordering remain unchanged. The internal `PlannedFile[]` staging seam is removed from the generate execution path.

## Testing

- Fail-on-old renderer test: hold presentation resolution open across more pages than the concurrency bound and assert that active renders never exceed the bound. The old unbounded `Promise.all` starts every page and fails this assertion.
- Integration coverage: compare all generated bytes and the ordered created/updated/skipped path arrays across the streaming path, including same-timestamp no-op regeneration and version-time selected-page regeneration.
- Durable affordable-cardinality curve regression: run two faithful nested-source rungs under memory instrumentation, assert non-zero `payloadBatchCandidates` for the all-extracted set, assert the larger generate RSS does not grow faster than cardinality, and retain existing mixed/recursive sequential-path assertions.
- Full local gates before PR: `deno task test`, `deno task fmt:check`, `deno task lint`, and `deno task check`.
- Acceptance probe: fresh current-only meshes at N=500, 1,000, and 1,700 with 1,024-byte terms and source `catalog/source`; fixed generated timestamp; capture wall/max RSS and timing; verify post-weave pending zero, page claims, source facts, non-HTML hashes, and zero-create/zero-update same-timestamp standalone generation.

Fail-on-old was recorded before production changes: the renderer test observed 9 active renders against the bound of 4. Final gates: `deno task test` 838 passed / 0 failed, with `deno task fmt:check`, `deno task lint`, `deno task check`, and `deno task queue check` all green. The N=1,700 acceptance run preserved all 5,108 non-HTML hashes and returned 0 created / 0 updated pages at the same timestamp.
